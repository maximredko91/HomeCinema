# Home Cinema

Личный медиацентр для Android: смотрит фильмы, сериалы, мультфильмы и
мультсериалы прямо с сетевого диска (SMB) — без стриминговых сервисов,
подписок и загрузки чего-либо на сторонние серверы.

Лицензия: [MIT](LICENSE).

## Возможности

### Библиотека
- **Несколько источников SMB одновременно** (SMB2/3, гостевой доступ или
  логин/пароль) — например, отдельные шары для фильмов и сериалов на разных
  дисках/роутерах. Управляются в Настройках: добавить/изменить/удалить,
  у каждого своя проверка подключения. Пароли хранятся зашифрованными
  (`EncryptedSharedPreferences`, ключ — в Android Keystore устройства), а не
  в открытом виде в базе данных приложения.
- Сканирование: рекурсивный обход папок, поиск видеофайлов, `.nfo` (формат
  Kodi), постеров и кадров (`fanart`). Библиотека кэшируется локально (Room) —
  список открывается мгновенно, сеть нужна только при сканировании и
  воспроизведении.
- **Автообновление** — при запуске приложения источники проверяются на новые
  файлы (не чаще раза в сутки), если это не отключено в настройках.
- Один недоступный источник (например, спящий NAS) не блокирует
  сканирование остальных.
- **Категории**: Всё / Фильмы / Сериалы / Мультфильмы / Мультсериалы.
  Мультфильмы и мультсериалы определяются автоматически по жанру в `.nfo`
  (Animation/Anime/Мультфильм и т.п.).
- **Поиск и фильтры по требованию** — иконки поиска и фильтров в шапке вместо
  постоянно закреплённой панели: поиск (по названию, описанию, актёрам,
  режиссёру) разворачивается прямо в заголовке, а категория/жанр/год/
  сортировка собраны в одном выезжающем снизу листе — не занимают место на
  экране и не мешают прокрутке списка.
- **Коллекции** — отдельная вкладка, группирует фильмы по тегу `<set>` из
  `.nfo` (например, серии фильмов вроде Бондианы). Позиция прокрутки
  запоминается при входе/выходе из коллекции.
- **Алфавитный указатель** — полоса с буквами сбоку от сетки для быстрой
  прокрутки по списку, отключается в настройках; плюс кнопки быстрого перехода
  в начало/конец списка.
- **Продолжить просмотр** — ряд над сеткой с недосмотренными фильмами,
  мультфильмами и сериями, отсортированный по давности; тап сразу возобновляет
  воспроизведение с прерванного места.
- Карточка тайтла показывает постер, название, жанр, год, а также прогресс
  просмотра (полоса снизу) или значок «просмотрено».
- Число колонок в сетке (2 или 3) настраивается.

### Сериалы
- Разбиты на сезоны и серии. Карточка сериала открывает список серий с
  описанием, миниатюрой (`*-thumb.jpg` или картинка с тем же именем, что и
  видео — обе конвенции Kodi), прогрессом просмотра, своим воспроизведением
  и загрузкой для каждой серии.
- Шапка экрана сериала показывает кадр (fanart), постер, метаданные,
  описание, режиссёра и актёров — как у фильма.

### Карточка тайтла (описание)
- Кадр из фильма (fanart) как баннер вверху экрана.
- Год, рейтинг, длительность, страна, жанры.
- Описание, режиссёр, актёры (парсятся из `.nfo`).
- **Зум изображений** — тап по кадру или постеру открывает полноэкранный
  просмотр с пинч-зумом и перетаскиванием.

### Воспроизведение
- Media3/ExoPlayer, стриминг по SMB без предварительного скачивания, либо
  локальная скачанная копия, либо внешний плеер (например, VLC) — выбор
  поведения настраивается (спрашивать каждый раз / всегда внутренний /
  всегда внешний).
- Полноэкранный иммерсивный режим (системные панели скрыты и не мешают
  просмотру), экран не гаснет во время воспроизведения.
- **Продолжение просмотра** — позиция сохраняется автоматически, при
  повторном открытии предлагается досмотреть с прерванного места.
- Переключение **субтитров** и **аудиодорожек** (кнопки появляются, только
  если они есть в файле).
- **Жесты**: свайп вверх/вниз слева — яркость, справа — громкость, с
  индикатором на экране; тап — показать/скрыть элементы управления (пока
  элементы управления показаны, жесты яркости/громкости уступают место
  обычным нажатиям на кнопки плеера).
- **Скачивание для просмотра офлайн.** Прогресс, значок на постере, раздел
  «Загрузки» с возможностью запустить или удалить.

### Настройки приложения
- Источники SMB (см. выше).
- Режим воспроизведения: внутренний плеер / внешний / спрашивать.
- Тема: системная / светлая / тёмная / OLED (глубокий чёрный).
- Акцентный цвет — на выбор несколько вариантов.
- Число колонок в сетке (2 или 3).
- Алфавитный указатель — вкл/выкл.
- Автообновление библиотеки — вкл/выкл.
- Очистка локального кэша обложек.
- «О приложении» — версия, список возможностей, использованные технологии,
  лицензии открытого кода; сворачивается в один заголовок-спойлер, чтобы не
  занимать место, пока не нужно.

## Структура проекта

```
app/src/main/java/com/homecinema/library/
├── data/
│   ├── smb/        SmbManager (jcifs-ng, контексты по каждому источнику) + SmbDataSource для ExoPlayer
│   ├── nfo/        NfoParser — парсер .nfo (movie/tvshow/episodedetails), включая set/actor/director/runtime
│   ├── scanner/    LibraryScanner — обход всех источников: сериалы (сезоны/серии) + фильмы/мультфильмы
│   ├── download/   DownloadManager — копирование видео с SMB на телефон с прогрессом
│   ├── db/         Room: MediaItemEntity, SmbSourceEntity + DAO
│   ├── repository/ LibraryRepository — единая точка входа для UI, миграция легаси-конфига
│   └── settings/   SettingsStore — DataStore: тема, плеер, автосканирование и т.п.
└── ui/
    ├── screens/    LibraryScreen, DetailScreen, ShowDetailScreen, DownloadsScreen, PlayerScreen, SettingsScreen
    ├── components/ MediaPosterCard, DownloadControlRow, ZoomableImageDialog
    ├── navigation/ AppNavHost
    ├── viewmodel/  LibraryViewModel + LibraryFiltering — фильтры/поиск/сортировка/коллекции (чистая функция, юнит-тестируется)
    └── theme/      Тёмная/светлая/OLED темы, акцентные цвета

app/src/test/        Юнит-тесты (JVM, без эмулятора) — парсер .nfo, фильтрация/сортировка, тема, мелкие хелперы
app/src/androidTest/  Инструментальные Compose-тесты (нужен эмулятор/устройство)
```

## Как собрать

1. Открыть папку `HomeCinema` в Android Studio (Ladybug/Meerkat или новее).
2. Дать Gradle синхронизироваться — он скачает зависимости
   (Compose, Media3, Room, jcifs-ng, Coil, DataStore) из Maven Central/Google.
   Проект собирается Gradle 9.6.1 + AGP 9.3.1 + Kotlin 2.3.10; JDK для демона
   Gradle определяется автоматически (`gradle/gradle-daemon-jvm.properties`).
3. Запустить на устройстве/эмуляторе в той же сети, что и роутер/NAS (Run ▶),
   либо собрать APK: `./gradlew assembleDebug`
   (файл — `app/build/outputs/apk/debug/app-debug.apk`).

> Обновление базы: схема Room периодически меняется вместе с новыми
> функциями, миграция настроена как разрушающая (`fallbackToDestructiveMigration`),
> так что при первом запуске новой версии локальный кэш библиотеки
> пересоздаётся — просто запустите сканирование заново. Настройки SMB и
> внешнего вида при этом не теряются (хранятся отдельно, в DataStore); пароли
> источников (в зашифрованном хранилище) — тоже.

## Релизная сборка

`assembleRelease` собирает минифицированный (R8 + `shrinkResources`) APK.
Чтобы он был подписан, создайте локальный keystore и `keystore.properties`
в корне репозитория (оба уже в `.gitignore` — никогда не коммитятся):

```bash
keytool -genkeypair -v -keystore app/release.keystore -alias homecinema \
  -keyalg RSA -keysize 2048 -validity 10000
```

```properties
# keystore.properties
storeFile=app/release.keystore
storePassword=...
keyAlias=homecinema
keyPassword=...
```

Без этих файлов `assembleRelease` всё равно соберётся, но APK останется
неподписанным. **Потеря keystore означает невозможность обновить уже
установленные у кого-либо копии приложения той же подписью** — храните
файл и пароли отдельно от репозитория (менеджер паролей/зашифрованный диск).

## Тесты

- **Юнит-тесты** (JVM, устройство не нужно): `./gradlew test`. Покрывают
  парсер `.nfo` (включая разбор `<set>`/`<actor>`/`<director>`/`<runtime>`),
  разбор номеров серий по имени файла, фильтрацию/сортировку/поиск библиотеки,
  разрешение темы (система/светлая/тёмная/OLED) и мелкие хелперы.
- **Инструментальные Compose-тесты** (`app/src/androidTest`) требуют
  подключённое устройство или эмулятор: `./gradlew connectedAndroidTest`.
- **CI** (`.github/workflows/ci.yml`): на каждый push/PR в `master` —
  юнит-тесты и debug-сборка на Ubuntu, плюс инструментальные тесты на
  macOS-раннере с эмулятором (там аппаратное ускорение доступно всегда,
  в отличие от многих локальных Windows-машин).

## Первый запуск

1. Открыть значок шестерёнки (настройки) → «Источники (SMB)» → «Добавить
   источник».
2. Указать:
   - **Название** — как источник будет называться в списке (например,
     «Гостиная NAS»).
   - **IP адрес** — например `192.168.1.1`.
   - **Имя общей папки (share)** — как она называется в списке сетевых папок
     роутера/NAS (Keenetic обычно называет её по имени диска, например
     `disk1_ssd1`).
   - **Подпапку внутри шары** — если фильмы лежат не в корне шары, а,
     например, в `Video/Movies`.
   - Логин/пароль (если на шаре включена аутентификация) либо переключатель
     «Гостевой доступ».
3. Нажать «Проверить подключение», затем «Сохранить». При необходимости —
   добавить ещё один источник тем же способом.
4. На главном экране нажать значок обновления — начнётся сканирование всех
   источников.

## Формат .nfo и структура папок

Фильмы/мультфильмы — по одной папке на тайтл:

```
Movies/
  Интерстеллар (2014)/
    Interstellar.mkv
    Interstellar-poster.jpg     (или poster.jpg / folder.jpg / cover.jpg)
    Interstellar-fanart.jpg     (кадр из фильма, показывается на странице описания)
    movie.nfo        <movie><title>...</title><year>...</year><genre>...</genre>
                      <runtime>...</runtime><country>...</country>
                      <director>...</director><actor><name>...</name></actor>
                      <set><name>Коллекция</name></set>...
```

Постер и кадр ищутся как по фиксированным именам (`poster.jpg`,
`fanart.jpg` и т.п.), так и по имени видеофайла с суффиксом
(`Interstellar-poster.jpg`) — так их обычно называют Kodi/Radarr.

Сериалы/мультсериалы — папка с `tvshow.nfo` в корне и подпапками по сезонам:

```
TV/
  Улица Сезам/
    tvshow.nfo        <tvshow><title>...</title><genre>Animation</genre>...
    poster.jpg
    fanart.jpg
    Season 01/
      S01E01.mkv
      S01E01.nfo      <episodedetails><title>...</title><season>1</season><episode>1</episode>...
      S01E01.jpg      (или S01E01-thumb.jpg — обе конвенции распознаются как миниатюра серии)
      S01E02.mkv
      S01E02.nfo
```

Если у серии нет отдельного `.nfo` или в нём не указаны `<season>`/`<episode>`,
сканер попытается определить номер сезона/серии по имени файла (`S01E02`,
`1x02`). Если и это не получится — серии внутри сезона нумеруются по порядку
обнаружения на диске.

## Известные ограничения / что можно доработать дальше

- Загрузка идёт в фоновом coroutine-scope приложения — переживает переход
  между экранами, но не переживает полное закрытие/выгрузку процесса
  Android. Для по-настоящему надёжных фоновых загрузок (уведомление в шторке,
  докачка после перезапуска и т.п.) стоит вынести это в `WorkManager` или
  foreground `Service`.
- Определение "мультфильм vs фильм" и "мультсериал vs сериал" — эвристика по
  ключевым словам в жанре (`Animation`, `Anime`, `Мультфильм`, `Cartoon`).
  Если жанр не заполнен scraper'ом, тайтл попадёт в обычную категорию
  "Фильмы"/"Сериалы".
- Для внешнего плеера используется системный `Intent.ACTION_VIEW`: если файл
  скачан — передаётся локальная ссылка через `FileProvider` (открывается
  любым плеером), если нет — `smb://` ссылка (сработает с плеерами, которые
  сами умеют читать SMB, например VLC).
- Автообновление библиотеки привязано к жизненному циклу главного экрана
  (фактически — к запуску приложения), а не к настоящему фоновому
  расписанию (`WorkManager`); пока приложение закрыто, обновления не
  происходит.
- Раскладки под Android TV / управление с пульта (D-pad) нет — интерфейс и
  жесты плеера (свайпы яркости/громкости, алфавитный указатель) рассчитаны
  на тачскрин.
